==================================================
1. 프로젝트 개요
==================================================

목적: 게임서버 프로그래머 포지션 이직을 위한 포트폴리오 프로젝트를
실제로 손으로 설계·구현한다.

핵심 명제: 만드는 것 자체가 실력 증명이 되어야 한다.
AI나 기성 프레임워크가 핵심 로직을 대신 해결하면 포트폴리오로서
가치가 없다.

장르: 로그라이크 덱빌더 + 1:1 턴제 PvP 듀얼
플랫폼: 반응형 WebGL (PC/모바일 브라우저 공용, 가로모드)
기술 스택: Unity(C#) 클라이언트 + ASP.NET Core(C#) + SignalR 서버


==================================================
2. 핵심 개발 원칙
==================================================

원칙 1. 바이브코딩 금지 — 직접 이해하고 설명 가능한 코드만 작성한다.

원칙 2. AI는 보일러플레이트만, 핵심 로직은 직접 작성한다. (13번 섹션 경계선 참고)

원칙 3. 콘텐츠 양보다 시스템 완성도 — 카드 수보다 상태머신/검증
       로직의 견고함이 우선한다.

원칙 4. 서버 권위(Authoritative Server) 우선 — 클라이언트는 판정하지
       않는다. 항상 서버가 검증한 결과만 신뢰한다.

원칙 5. 기성 멀티플레이어 프레임워크(Photon/Mirror/FishNet) 사용 금지
       — 매치메이킹/룸 관리/상태 동기화를 직접 설계한다.


==================================================
3. 세계관 및 게임 컨셉
==================================================

한 줄 세계관:

당신은 이름 없는 프리랜서 해커다. 다크넷에 접속해 기업 서버망 깊숙이
침투하며 실력을 증명하고, 그 과정에서 마주치는 다른 해커와 실시간으로
결투한다. 승부의 순간, 메인프레임은 그 누구의 편도 들지 않는다 —
오직 규칙만을 강제한다.

("메인프레임이 규칙만 강제한다"는 설정은 실제 서버 권위 검증
아키텍처를 세계관으로 감싼 장치다. 면접에서 "왜 이런 설정을 넣었는가"
질문에 기술적 근거로 답할 수 있다.)

핵심 용어 (게임 내 명칭):

체력           -> 시스템 무결성 (Integrity, INT)
자원(마나)      -> 대역폭 (Bandwidth, BW)
공격 카드       -> 익스플로잇 (Exploit)
방어 카드       -> 방화벽 (Firewall)
드로우 카드     -> 스캔 (Scan)
자원획득 카드   -> 오버클럭 (Overclock)
디버프(지속피해) -> 트레이스 (Trace)
리더보드        -> 다크넷 랭킹 (Darknet Ranking)
영구 재화       -> 데이터 조각 (Data Shard)
매치메이킹      -> 업링크 (Uplink)

아트 톤: 사이버펑크, 플랫 벡터 + 네온 글로우
텍스트 톤: 시크한 터미널 미니멀 (짧고 건조한 시스템 로그체)

4. 캐릭터 기획
==================================================

플레이어는 커스텀 아바타를 갖지 않고, 3개 아키타입(플레이스타일) 중
하나를 선택해 대결한다. 각 아키타입은 게임 내 실루엣 아바타와,
세계관상 그 스타일을 상징하는 "전설의 해커" 캐릭터를 갖는다. 이
캐릭터들은 튜토리얼 내레이션, 로딩 팁, CHECKPOINT 노드의 PvE 상대로
등장한다.

--------------------------------------------------
[침투형] INTRUSION — 초록 네온 / 후드 실루엣
--------------------------------------------------
상징 캐릭터: "ZERO-DAY"
배경: 대기업 세 곳을 무너뜨린 전설적 침투 전문가. "잡히기 전에
      끝낸다"가 신조. 방어를 아예 설계하지 않는 것으로 유명하다.
플레이스타일: 대역폭을 빠르게 태워 큰 피해를 내는 공격형. 방어가
      약해 상대보다 먼저 끝내야 하는 리스크-리워드.
대표 메커니즘: "체인" — 한 턴에 익스플로잇 카드를 연속 사용할수록
      다음 익스플로잇 피해가 누적 증가.
로딩 팁 예시: "ZERO-DAY: 방어는 시간 낭비다. 상대가 반격할 틈을
      주지 마라."

--------------------------------------------------
[방어형] FIREWALL — 청록 네온 / 회로판 패턴 실루엣
--------------------------------------------------
상징 캐릭터: "SENTINEL"
배경: 한때 대기업 보안팀장이었다가 전향한 방어 전문가. 업계에서는
      "뚫리지 않는 벽"이라 불린다.
플레이스타일: 방어막을 쌓고 반격하는 지구전형. 상대의 대역폭을
      고갈시키고 역으로 되받아친다.
대표 메커니즘: "오버실드" — 방어막이 일정 수치(15) 이상 쌓이면
      초과분이 상대에게 반사 피해로 전환.
로딩 팁 예시: "SENTINEL: 서두르는 쪽이 먼저 무너진다."

--------------------------------------------------
[정보형] INFOTECH — 마젠타 네온 / 눈 아이콘 실루엣
--------------------------------------------------
상징 캐릭터: "GHOST"
배경: 정보 브로커 출신. 모든 것을 알고 있는 존재로 알려져 있으며,
      직접 공격보다 서서히 스며드는 방식을 선호한다.
플레이스타일: 카드를 순환시키고 트레이스(지속피해)를 축적시켜
      터뜨리는 콤보/엔진 빌드.
대표 메커니즘: "감염" — 상대에게 걸린 트레이스 스택 수에 비례해
      추가 피해를 주는 카드들이 존재.
로딩 팁 예시: "GHOST: 한 방보다, 서서히 무너뜨리는 편이 확실하다."


CHECKPOINT 노드 활용:

각 런의 CHECKPOINT(최종 보안 시스템)에서는 위 3명 중 1명이 무작위로
등장하는 강화 PvE 전투로 구성한다. 승리 시 해당 캐릭터 테마의
코스메틱(아바타 컬러 변형, Stretch)을 보상으로 지급 가능.

5. 전투 디자인
==================================================

5.1 턴 구조

1. 매치 시작 시 선공 결정 (매치메이킹 성사 시 서버가 무작위 결정)
2. 턴 시작: 대역폭 전량 리필 (라운드마다 최대치 소폭 증가 - 예:
   1턴 3BW, 2턴 4BW, 3턴 이후 5BW 고정 상한)
3. 카드 드로우: 매 턴 시작 시 손패가 5장 미만이면 5장까지 보충
4. 카드 사용: 대역폭이 허용하는 한 자유롭게 여러 장 사용 가능
5. 턴 종료 선언 (수동 종료 또는 제한시간 초과 시 자동 종료)
6. 턴 종료 처리: 트레이스(지속피해) 일괄 적용 -> 임시 방어막 소멸
   (단, "격리 프로토콜" 등 유지 명시된 카드 효과는 예외)
7. 상대 턴으로 전환

5.2 자원 규칙

대역폭은 턴 종료 시 이월되지 않는다 ("Use it or lose it").
이는 Slay the Spire류 로그라이크 덱빌더의 표준 관습을 따른 것으로,
매 턴 판단의 밀도를 높이기 위함이다.

5.3 승패 조건

상대의 시스템 무결성이 0 이하가 되는 순간 즉시 승리 처리한다.
턴제 순차 처리이므로 "동시 사망" 상황은 발생하지 않는다 —
카드 효과는 발동된 순서대로 하나씩 서버에서 처리되며, 처리 도중
승패 조건이 충족되면 그 즉시 나머지 처리를 중단하고 매치를 종료한다.

5.4 턴 제한시간

턴당 30초 제한. 초과 시 서버가 강제로 턴을 종료 처리한다.
사용하지 않은 카드는 소멸하지 않고 다음 턴 손패에 남는다
(단, 손패 상한 10장 초과 시 초과분은 폐기).
반복 타임아웃에 대한 별도 페널티는 MVP에서 두지 않는다
(네트워크 지연 등으로 인한 선의의 사용자 보호).

5.5 카드 효과 처리 우선순위

MVP는 스택/인터럽트 시스템 없이 단순화한다. 카드는 사용 즉시
서버에서 순차 처리되며, 동시 발동 개념 자체가 존재하지 않는다
(한 플레이어가 한 번에 하나의 의도만 보낼 수 있음). 트레이스는
"턴 종료 처리" 시점에 일괄 적용한다.

5.6 접속 끊김 처리

기술 스펙 10번 섹션(룸/세션 상태머신)과 연동:
Reconnecting 상태에서 90초 내 재접속 시 현재 게임 상태 스냅샷을
그대로 재전송하여 이어서 진행한다. 초과 시 Abandoned 처리, 남은
플레이어 승리.

(원래 60초였으나, 모바일 브라우저는 앱 전환/화면 잠금만으로도
WebSocket이 쉽게 끊기는 특성이 있어 90초로 완화. 모바일에서
데스크톱보다 재접속이 잦을 수 있다는 점은 17번 섹션 리스크에
알려진 제약사항으로 명시하고, 별도의 추가 기능 개발은 하지 않는다
— 이 프로젝트의 핵심 증명 포인트인 서버 권위/상태머신과 직접
관련이 없는 지엽적 문제이기 때문)

[트레이스 인젝션] 1 | 상대에게 트레이스 2 부여
[데이터 마이닝] 2 | 카드 1장 뽑고 대역폭 1 획득
[컴파일] 0 | 손패 무작위 1장 이번 턴 비용 1 감소
[코럽션] 2 | 상대 트레이스 스택 수만큼 추가 데미지
[오버클럭] 1 | 이번 턴 대역폭 2 추가 획득
[웜] 2 | 상대에게 트레이스 1 부여, 매 턴 종료 시 자동 1씩 증가
[풀 인덱스] 3 | 덱 전체 확인 후 원하는 카드 1장을 손으로

밸런싱 메모: 위 수치는 시작점이며 플레이테스트 후 조정 전제.
밸런스 자체보다 "카드 효과 시스템이 데이터 기반으로 안전하게
동작하는가"가 더 중요한 포트폴리오 포인트.

6.3 로그라이크 노드맵 구조

SECURITY NODE   PvE 전투 (방화벽 AI, 감시봇 등, 5~10종)
MARKET NODE     상점 (데이터 조각/대역폭으로 카드 구매·삭제)
DATA CACHE      랜덤 이벤트 (리스크/리워드 선택지)
UPLINK NODE     매치메이킹 발생 지점 (실제 플레이어와 PvP)
CHECKPOINT      런의 최종 보안 시스템 (4번 섹션 상징 캐릭터 등장)

진행 예시: 시작 -> SECURITY -> DATA CACHE -> MARKET -> UPLINK(PvP)
          -> SECURITY -> UPLINK(PvP) -> CHECKPOINT -> 런 종료

6.4 메타 프로그레션

런 중 임시(런 종료 시 소멸): 현재 덱 구성, 무결성, 대역폭
영구 유지: 데이터 조각(PvP 승리·SECURITY 클리어 시 획득) ->
          다음 런 신규 카드 언락에 사용 (코스메틱은 Stretch)
랭킹: 다크넷 랭킹 — MVP는 단순 승수 집계, ELO는 Stretch

6.5 PvE / 봇 상대 AI (규칙 기반, 공용 시스템)

SECURITY NODE 몬스터(5~10종), TRAINING NODE 튜토리얼 상대, 그리고
7.7절의 매치메이킹 봇 폴백은 전부 **동일한 규칙 기반 AI 로직 하나를
재사용**한다.

행동 규칙 (단순 상태 기반):
- 자기 무결성이 50% 이상이면 공격(익스플로잇) 카드 우선 사용
- 50% 미만이면 방어(방화벽) 카드 우선 사용
- 대역폭이 남고 사용 가능한 카드가 더 있으면 반복, 없으면 턴 종료

몬스터/봇의 다양성은 이 규칙 위에 서로 다른 카드풀(공격형/방어형/
상태이상형)만 배정해서 만든다 — 새로운 AI를 종류별로 따로 만들지
않는다.

구현 방식: 이 AI는 서버 내부에서 "의도(Intent)"를 생성해 11번 섹션의
서버 권위 검증 파이프라인에 그대로 태운다. 즉 몬스터/봇도 실제
플레이어와 동일한 방식으로 취급되며, 검증 로직을 이중으로 만들
필요가 없다.

7. 서비스 기획
==================================================

7.1 서비스 범위 정의

이 프로젝트는 포트폴리오 목적의 단일 배포 서비스로, 대량 동시접속을
전제하지 않는다. 다만 설계 자체는 실서비스 수준의 구조(서버 권위,
상태머신, 재접속 처리)를 따른다 — "작지만 제대로 만든 서비스"가
목표다.

7.2 온보딩 플로우

1. 첫 실행 -> 회원가입 (닉네임, 이메일, 비밀번호)
2. 짧은 튜토리얼: TRAINING NODE라는 이름의 PvE 대결에서 기본 조작
   (카드 사용, 턴 종료, 방어 개념)을 학습
3. 튜토리얼 종료 후 첫 로그라이크 런 시작 가능

7.3 계정 관리 (MVP 범위)

- 회원가입/로그인 (JWT)
- 비밀번호 변경
- 계정 삭제 (최소 기능만)
- 게스트 로그인, 소셜 로그인은 Stretch

7.4 커뮤니티/신고 기능

MVP 스코프 아웃. 실사용자 다수를 대상으로 한 서비스가 아니므로
신고/제재 시스템은 만들지 않는다. 다만 닉네임에 대한 최소한의
금칙어 필터 정도는 회원가입 시 적용 (직접 구현하는 간단한 로직).

7.5 리텐션 장치

MVP에는 없음 (명시적으로 제외). 데일리 챌린지, 시즌 랭킹은
Stretch 단계에서 고려. "Streak 자체가 목표가 되면 안 된다"는
DevGrowth 논의 당시의 원칙을 여기서도 동일하게 적용 — 리텐션
장치보다 코어 루프의 완성도가 우선.

7.6 운영/모니터링

- 로깅: 서버 요청, 예외, 매치 시작/종료, 상태머신 전이를 기록
  (Serilog)
- 개인정보/민감정보는 로그에 남기지 않는다
- 모니터링 대시보드 등은 Stretch (Phase 7급 인프라는 MVP 제외)

7.7 매치메이킹 대기시간 초과 처리 (봇 폴백)

문제: 이 게임은 1:1 PvP라 실제 사용자가 거의 없는 포트폴리오
단계에서는 매치메이킹 큐에 상대가 없을 수 있다. 이러면 면접관이
직접 접속해도 상대를 못 찾아 무한 대기하게 되고, 개발 중 기능
검증도 항상 클라이언트 2개를 동시에 띄워야 하는 불편이 있다.

해결: 매치메이킹 큐에서 **15초 내** 상대를 찾지 못하면, 서버가
6.5절의 규칙 기반 봇을 자동으로 매칭한다. 사용자 관점에서는
"TARGET ACQUIRED: UNKNOWN_ENTITY" 같은 문구로 안내하며, 실제
플레이 경험(서버 권위 검증, 상태 동기화)은 실사용자와 대결할 때와
완전히 동일하다. 이 덕분에 개발자 본인의 기능 검증도, 면접관의
1인 시연도 항상 즉시 가능하다.

[S-05] 로그라이크 노드맵 화면
--------------------------------------------------
목적: 런 진행 경로 선택
구성: 화면 하단에서 상단으로 이어지는 노드 경로(6.3 노드 타입별

     다음 노드만 활성화(하이라이트), 나머지는 반투명 처리
좌상단: 현재 무결성/대역폭 상한/보유 데이터 조각 상시 표시
전환: 노드 선택 -> 해당 노드 화면으로 이동

--------------------------------------------------
[S-06] SECURITY NODE (PvE 전투 진입) / [S-07] 듀얼 화면
--------------------------------------------------
목적: 전투 진행 (PvE, PvP 공용 레이아웃)
구성 (가장 중요한 화면, 상세 기술):

  상단 영역 (상대 정보):
    - 좌측: 아키타입 실루엣 아바타 + 닉네임(PvE는 캐릭터명)
    - 무결성 게이지 (붉은 계열 바 + 수치)
    - 대역폭 게이지 (청색 계열 바 + 수치)
    - 트레이스 스택 아이콘(있는 경우만, 스택 수 표시)
    - 손패 장수만 표시 (카드 뒷면 아이콘 x N)

  중앙 영역:
    - 좌우로 분리된 필드 표시 (상대 위/내 아래)
    - 중앙에 턴 표시기 ("YOUR TURN" / "REMOTE TURN") +
      턴 제한시간 원형 게이지(30초 카운트다운)
    - 우측 하단에 터미널 스타일 전투 로그 콘솔(스크롤 가능,
      "ZERO-DAY used [Brute Force]. -12 INTEGRITY." 같은 로그)

  하단 영역 (내 정보 + 손패):
    - 좌측: 내 아바타 + 무결성/대역폭 게이지 + 트레이스 표시
    - 중앙: 손패 카드 UI (부채꼴 배치, 최대 10장), 카드 호버 시
      확대 + 사용 가능 여부(대역폭 부족 시 반투명 처리)
    - 우측: "END TURN" 버튼 (대역폭 소진 여부와 무관하게 항상 활성)

  인터랙션:
    - 카드 드래그하여 필드 중앙으로 이동 시 사용 시도
    - 타겟이 필요한 카드는 드래그 시 상대 진영에 조준선(네온 라인)
      표시
    - 서버 응답 대기 중에는 해당 카드에 로딩 스피너 오버레이
      (서버 권위 검증을 시각적으로도 인지시키는 장치 —
      "클라이언트가 즉시 반영하지 않고 서버 승인을 기다린다"는
      것을 자연스럽게 노출하는 연출)

--------------------------------------------------
[S-08] DATA CACHE (이벤트) 화면
--------------------------------------------------

     선택 결과는 즉시 텍스트로 출력 후 노드맵 복귀

[S-09] MARKET NODE (상점) 화면
--------------------------------------------------

--------------------------------------------------
[S-10] 업링크(매치메이킹) 대기 화면
--------------------------------------------------

     "TARGET ACQUIRED" 문구 출력 후 자동으로 S-07 전환
비고: 15초 초과 시 7.7절 봇 폴백이 자동 매칭되며, 이때는 상대

--------------------------------------------------

카드 사용 불가(자원 부족)     INSUFFICIENT BANDWIDTH.
세로모드 접속 시              ROTATE DEVICE TO LANDSCAPE_
봇 매칭 성사                 TARGET ACQUIRED: UNKNOWN_ENTITY
재접속 유예 중(모바일 등)     LINK UNSTABLE. AWAITING RECONNECT...

10. 시스템 아키텍처 (기술 요약)
==================================================

Unity Client (WebGL)
   |-- HTTP: Auth, 리더보드/매치기록 조회 --> REST API
   |-- WebSocket(SignalR): 실시간 듀얼 통신 --> Match Hub
                                                  |
                                          Application Layer
                                          - MatchmakingService
                                          - RoomManager(상태머신)
                                          - GameRuleValidator(서버 권위)
                                          - CardEffectResolver
                                                  |
                                          Domain Layer (Card, Deck, RunState)
                                                  |
                                          Infrastructure(EF Core) -> PostgreSQL

Domain은 다른 계층을 참조하지 않는다.

룸/세션 상태머신:
Waiting -> InProgress(턴 루프) -> Reconnecting -> Completed/Abandoned
(전이 규칙, 재접속 처리는 5.6절 및 원 기술기획서 10번 섹션 참고)

서버 권위 검증 절차:
1. 현재 턴 소유자 확인 2. 카드 소유 확인 3. 자원 확인
4. 효과 적용 5. 결과 브로드캐스트

보안/암호화 (MVP 필수 — 표준 보안 위생):
- REST API는 HTTPS, SignalR은 WSS(TLS 기반 WebSocket)로만 통신
- 비밀번호는 bcrypt로 해싱하여 저장 (평문/가역 암호화 저장 금지)

API 문서 공개:
- Swagger/OpenAPI UI를 배포 환경에서도 `/swagger` 경로로 공개하여,
  코드를 보여주지 않아도 실제 API 구조를 URL 하나로 증명할 수
  있게 한다. README에 링크 명시.

  무시하고 정상 규칙대로만 처리한다.
- 한쪽 네트워크가 끊겼다가 재접속해도 게임이 정상 이어진다.
- 면접관이 링크로 직접 접속하면, 실사용자가 없어도 15초 내 봇
  폴백으로 즉시 대결을 시작할 수 있다 (7.7절 — 실사용자 매칭과
  봇 매칭 모두 동일한 서버 권위 검증 경로를 탄다).
- 클라이언트를 열지 않고도 `/swagger` 경로로 실제 API 구조를
  확인할 수 있다.
- 본인이 매치메이킹/상태머신/서버 검증 로직 각각에 대해 "왜 이렇게
  설계했는지"를 막힘없이 설명할 수 있다.
